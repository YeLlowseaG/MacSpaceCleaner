开发者空间

DerivedData 可以删，但代价不是零

它里面是编译中间产物和代码索引，删掉不会丢源码、配置和已发布的东西。真正的代价是：下一次编译明显变慢，代码跳转和自动补全要重新建索引。知道这一点再决定，就不算亏。

直接看怎么删先看什么时候不该删

先搞清楚

DerivedData 里到底装了什么

默认位置是 ~/Library/Developer/Xcode/DerivedData，每个项目一个以「项目名 + 一串哈希」命名的目录。

Build：编译中间产物

目标文件、模块缓存、链接结果，以及构建出来的 .app。改一行代码后 Xcode 只需要重编一部分，靠的就是它。

Index：代码索引

支撑「跳转到定义」「查找引用」「自动补全」的数据。它不参与编译，但删掉之后第一次用这些功能会卡一阵。

Logs 和构建记录

每次构建的日志。体积不大，但排查编译问题时它是唯一线索。

为什么一个项目会有好几个目录

哈希里编码了 Xcode 版本和构建路径。换过 Xcode 大版本、或者项目路径变过，就会多出一份，旧的不会自动消失。

判断代价

删之前先对一下这几条

简单说：你只是想要回空间，就删；你马上就要编译或者调试，就先别删。

会丢的：没有

源码、Package.swift、Podfile、.xcconfig、资源文件、已归档的 Archives、已提交的代码 —— 全部不受影响，它们本来就不在 DerivedData 里。

会付的：一次全量编译

下次编译时所有源码都要重新编一遍。小项目几分钟，大项目（含大量 Swift 文件或 CocoaPods 依赖）可能十几分钟甚至更久。之后恢复正常增量编译。

会付的：索引重建

删掉之后，代码跳转和自动补全在索引重建完成前不可用，通常要等 Xcode 在后台跑一遍。这一步经常被忽略，但体验上最明显。

不该删的时机

刚 build 完准备跑测试、正在用 Instruments 抓性能、正在断点调试、或者马上要演示。这些场景下你会为省下的空间付出等编译的时间。另外删之前先退出 Xcode，避免它边写边删导致状态不一致。

动手

三种删法，效果完全不同

先确认你要的是哪一个目标，再选方法。

① 先看它有多大

du -sh ~/Library/Developer/Xcode/DerivedData

② 只清当前项目的构建产物（保留索引）

# 在 Xcode 里：Product → Clean Build Folder（Shift + Cmd + K）

③ 清掉所有项目的历史缓存（会重建索引）

rm -rf ~/Library/Developer/Xcode/DerivedData/*

三种方法的区别：Clean Build Folder 只动当前项目、保留索引、释放空间最少；直接清空整个目录释放最多，但所有项目下次打开都要重建索引。rm -rf 是永久删除，不进废纸篓，执行前请确认路径写对了 —— 路径末尾那串 /* 前面必须是 DerivedData/。

一个常见的坑

如果你的 DerivedData 不在默认位置

有些人为了把编译产物和项目放一起，在 Xcode → Settings → Locations → Derived Data 里改了位置。这样一来：

  • 默认目录 ~/Library/Developer/Xcode/DerivedData 可能是空的，你会以为「Xcode 不占空间」
  • 真正占空间的是你自定义的那个目录，得去那里清理
  • 清理工具只处理默认位置，自定义路径会被跳过 —— 这是有意的，避免误删项目目录里的东西

先确认位置再动手，比删错再去找备份省事得多。

常见问题

关于 DerivedData

删了会不会影响我的项目？

不影响项目本身。源码、依赖声明、配置文件和已归档的发布包都不在 DerivedData 里。删除后项目能正常编译，只是第一次要全量编译。

删掉之后需要重新 pod install 吗？

不需要。依赖的源码和 Pods 目录不在 DerivedData 里。重编时会重新编译这些依赖，但不需要重新安装。

为什么删了之后 Xcode 变卡了？

它在重建索引。打开 Xcode 后会自动在后台做，期间「跳转到定义」和自动补全可能不准或变慢。等状态栏的进度跑完就恢复了。

可以用 Xcode 自带的清理代替吗？

可以，但效果不同。Clean Build Folder 只清当前项目当前配置的产物并保留索引，比较保守；要一次性把历史缓存全部释放，需要直接处理整个 DerivedData 目录。

清理工具会不会连我的源码目录一起删？

不会。DerivedData 默认位置的父目录是 ~/Library/Developer，与项目目录完全不同。产品只操作明确允许的路径，并且在删除前再次校验路径、目录类型和符号链接。
