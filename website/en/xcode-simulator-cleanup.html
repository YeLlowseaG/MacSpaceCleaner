Developer storage

Old Xcode simulators are often the largest reclaimable block on your Mac

Every iOS or watchOS runtime is a complete system image, usually 4–9 GB each. Xcode does not delete the previous version when you upgrade, so they stack up to tens of gigabytes.

Understand it first

What a simulator runtime actually contains

Many people assume “the simulator” is a few temporary files, which is why they never think to clean it up. That is not what is on your disk.

Each runtime is a full system image

It contains every framework, resource and binary for that OS version. It is not a cache, so it is measured in gigabytes rather than megabytes.

They accumulate and never clean up

Each time Xcode targets a new OS version you download another runtime. The previous one stays on disk unless you deal with it.

Every platform accumulates separately

If you ship iOS and watchOS (or tvOS or visionOS), each platform keeps its own history of runtimes.

The only real use is compatibility testing

An old runtime exists for one purpose: testing your app on that specific OS version. If you never do that, it is worth nothing to you.

How to decide

Which runtimes to keep and which to delete

The rule is simple: keep the newest version for each platform, keep the rest only if you need them.

Always keep: the newest runtime per platform

That is the one your day-to-day development uses. Delete it and the simulator stops working until you download several gigabytes again.

Check your minimum deployment target

If your app supports iOS 17 and later, the iOS 16 runtime and anything older has almost no use to you.

Check whether you have a release obligation

If you are not compatibility testing on old systems, you do not need old runtimes. Shipping only requires the current version to run.

A wrong deletion is recoverable

Xcode Settings → Components lets you download any runtime again. The only cost is the download time.

Manual method

You can check this in Terminal without any tool

If all you want is to see how much you have, these two commands are enough. They only read, they delete nothing.

Size of each installed runtime

du -sh ~/Library/Developer/CoreSimulator/Profiles/Runtimes/*

Size of the regenerable shared cache

du -sh ~/Library/Developer/CoreSimulator/Caches/dyld

To delete manually, move the runtime folder for that version to the Trash in Finder rather than running a script. A safe sequence: delete only the oldest version first, confirm Xcode and your projects still behave, then continue with the others.

FAQ

Cleaning up Xcode simulators

Will this affect the project I am working on?

Not if you keep the newest runtime for each platform. An old runtime only runs a simulator on that OS version. If you no longer test against it, deleting it affects neither your code nor the simulator you use daily. When in doubt, delete only the oldest one or two.

Why is one runtime tens of gigabytes?

A single runtime is usually 4–9 GB, not tens of gigabytes. But several historical versions across iOS and watchOS add up to tens of gigabytes on a development machine, because each platform ships several new versions a year.

What is Caches/dyld and can I delete it?

It is the simulator's dynamic linker cache, rebuilt on demand. After deleting it, the first simulator launch regenerates it and is slower once. Installed runtimes and devices are unaffected.

Can I reinstall a runtime afterwards?

Yes. Xcode Settings → Components lets you download any OS runtime again. The cost is the download time.

Does cleaning touch my project files or source code?

No. Runtimes and device data live under ~/Library/Developer, separate from your project directories. The app only operates inside an explicit allowlist of cache and runtime paths, and never touches project files.
