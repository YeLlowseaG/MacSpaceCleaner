See it before you delete it

See what is really taking up your Mac, before you delete it

On a developer's Mac the biggest block is usually Xcode: old simulator runtimes, build caches and device support files add up to tens of gigabytes. Everyday app caches are listed the same way, each with its real size and marked regenerable or not. You decide what goes.

The interface

What is safe to delete, and what only looks like it

Recommended caches, optional caches, the three Xcode categories and personal data are shown in separate groups. Each group has its own selection boundary, and nothing happens until you decide.

What it finds

From Xcode to everyday app caches

Xcode storage

Old simulator runtimes are listed one by one per platform and version, with the newest version of each platform marked automatically. The build cache (DerivedData) and device support files can be handled separately. All three are regenerable, so removing them does not touch your source code or configuration. The five locations →

Developer tool caches

Package caches, temporary execution caches and download caches left behind by tools such as npm, pnpm, bun, Homebrew and Playwright. All of them are regenerated on demand.

App caches and logs

Browser component caches, update caches, offline webpages, speech models, dynamic wallpapers and temporary resources from apps such as WeChat and WPS. This group is unchecked by default.

Personal data is view-only

Downloads, iCloud Drive, WeChat chat data and WPS backups are shown for reference and never included in one-click cleanup.

Safety boundaries

Only known cache paths are eligible

Before deleting anything, the app checks its allowlist, the directory type and symbolic links again. Paths that do not pass these checks are skipped.
