开发者空间

Xcode 占了多少，其实取决于五块东西

开发机上「Xcode 占用」不是一坨黑盒。它由五个位置组成，每一块的性质完全不同：有四块是可重新生成的，有一块是你的发布记录，删了再也补不回来。先分开量，再决定删哪个。

拆开看

Xcode 的空间由这五块组成

前四块都在 ~/Library/Developer 下，和你的项目源码完全分开。第五块是 Xcode 本体。

1. 模拟器运行时

路径 CoreSimulator/Profiles/Runtimes。每个是一整套系统镜像，单个通常 4–9 GB。历史版本不会自动删除，是这块最占空间的部分。

2. 构建缓存 DerivedData

路径 Xcode/DerivedData。编译中间产物和索引。项目越多、编译越久，它越大，而且它只增不减。

3. 真机调试支持文件

路径 Xcode/iOS DeviceSupport（还有 watchOS、tvOS、visionOS）。每台插过的真机、每个系统版本各一份，换过手机的人最容易堆起来。

4. 归档 Archives ⚠️ 不要删

路径 Xcode/Archives。每次 Archive 打包的存档，含 dSYM 符号文件。这是你的发布记录，不是缓存。

5. 模拟器设备与共享缓存

CoreSimulator/Devices 是你建的那些模拟器设备，CoreSimulator/Caches/dyld 是可重建的动态链接缓存。

外加：Xcode 本体

在 /Applications 下，通常十几 GB。这是你每天要用的工具，不在任何清理范围内。

逐块判断

每一块能不能删、代价是什么

判断标准只有一条：删掉之后能不能重新生成，以及重新生成要花多久。

模拟器运行时 — 可以删

留每个平台的最新版，其余按需要。删掉后可以在 Xcode 的 Settings → Components 重新下载，代价是重新下几个 GB。这是单项释放空间最多的一块。详细判断方法 →

DerivedData — 可以删

删掉不丢源码、配置和已发布的东西，代价是下一次编译明显变慢，因为要重建索引和中间产物。刚 build 完要立刻跑测试的时候不要删。DerivedData 详解 →

真机调试支持文件 — 可以删

它是连接真机调试时从设备上抓的符号文件。删掉后下次连接那台设备会重新抓取，等几分钟。注意：如果你在用 Instruments 或 Crash 日志调试那台特定的设备，删了要重新等。

归档 Archives — 不要删

它保存的是你每次提交上架的构建和 dSYM 符号文件。删掉之后，历史版本的崩溃日志无法再符号化，也无法把同一个构建重新上传。它不属于可重建内容，任何清理工具都不该把它算进「可释放空间」。

模拟器设备与 dyld 缓存 — 可以删

设备是你自己建的，删掉等于重置模拟器状态；dyld 共享缓存按需重建，删后首次启动模拟器会慢一次。两者都不影响已安装的运行时。

先量再删

一条命令，把五块分别量出来

在终端里跑下面这条。它只读取，不删除任何东西，输出会按体积从小到大排列，最占空间的那块在最后。

分别查看每一块的体积

du -sh ~/Library/Developer/Xcode/* ~/Library/Developer/CoreSimulator/* 2>/dev/null | sort -h

重点看三个名字：DerivedData、iOS DeviceSupport、Profiles/Runtimes。如果你的开发机磁盘很紧，这三个加起来通常就是最大头。

量完之后，先只处理体积最大的那一块，删完确认 Xcode 和你的项目一切正常，再动第二块。一次全删虽然省事，但万一某个项目依赖了某个旧运行时，你会很难定位是哪一个。

动手顺序

如果只删一次，按这个顺序

  • 第一刀：旧版模拟器运行时 —— 释放最多，风险最低，按平台保留最新版即可
  • 第二刀：DerivedData —— 通常几个 GB 到几十 GB，删完接受一次慢编译
  • 第三刀：真机调试支持文件 —— 只删你不再持有的设备对应的版本
  • 第四刀：dyld 共享缓存 —— 收益最小，随时可重建
  • 不要碰：Archives —— 省下的空间换不回你的发布记录

常见问题

关于 Xcode 的磁盘占用

Xcode 一般会占多少？

取决于装了多少个模拟器运行时、以及有多少编译历史。刚装好的 Xcode 本体大约十几 GB；一旦装了几个 iOS 和 watchOS 运行时、项目又编译过一段时间，整个 ~/Library/Developer 到几十 GB 很常见，其中大部分是可重新生成的。

哪一块绝对不能删？

~/Library/Developer/Xcode/Archives。它是你每次 Archive 打包留下的存档，包含二进制和 dSYM 符号文件。删掉之后历史版本的崩溃日志无法再符号化，也无法重新上传同一个构建。它属于发布记录，不是缓存。

删了之后 Xcode 会不会坏？

可重新生成的部分不会。运行时可以重新下载，DerivedData 和共享缓存会自动重建，真机调试支持文件会在下次连接设备时重新抓取。代价是时间，不是数据。

为什么我的 DerivedData 越用越大？

它只增不减。每个项目的每次配置变更、每个 SDK 版本、每台模拟器架构都可能留下独立的中间产物，Xcode 默认不会清理。所以同一台机器上换过几次 Xcode 大版本之后，它经常是最大的一块。

清理会不会动到我的项目文件和代码？

不会。这五块全部在 ~/Library/Developer 和 /Applications 下，与你的项目目录分开。产品也只在明确允许的路径内操作，不触碰项目文件。
