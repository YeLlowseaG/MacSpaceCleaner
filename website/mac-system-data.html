macOS 存储

系统数据 100 多 G，但它不是一个文件夹

你在「关于本机 → 存储」里看到一大块「系统数据」，然后在访达里翻遍了也找不到它 —— 因为它根本不是磁盘上的某个目录，而是一个分类。搞清楚这一点，才谈得上清理。

先看最可能是哪几项直接开始量

先搞清楚

「系统数据」是一个分类，不是一块空间

macOS 把磁盘上的内容分成几类：应用程序、文稿、照片、音乐、邮件、系统数据……前几类都有明确归属，剩下所有不属于它们的，全被扫进「系统数据」。

它由很多东西拼成

设备备份、虚拟机磁盘、开发缓存、日志、邮件附件、本地快照、索引数据库 —— 它们唯一的共同点是「没被归到别的分类」。

所以没有「清除系统数据」按钮

不存在一个叫「系统数据」的文件夹可以删。任何声称能一键清掉它的工具，实际上是在删其中的某些具体路径。

它经常被「用出来」

备份一次 iPhone、拉几个 Docker 镜像、编译几个大项目，几个月后它就能无声无息地涨到几十甚至上百 GB。

数值本身也不精确

这个分类的数字是估算的，系统会先把文件归到已知分类，剩下的才累计到这里。所以它偶尔会跳动，不必纠结到小数点。

按可能性排序

最可能是这几项，从第一名开始查

下面大致按「实际占得多、又常被忽略」排序。你不需要全查，从前两项开始量通常就能找到答案。

① iPhone / iPad 备份

路径 ~/Library/Application Support/MobileSync/Backup。每次把 iPhone 插上 Mac 同步或备份，就会留一份完整设备备份，一份经常十几到几十 GB，而且每台设备多份。这是最容易超过 100 GB 的单项。

处理方式：在访达里按住 Option 打开「前往 → 资源库」进入该目录；或者更安全地在 系统设置 → 通用 → 储存空间 里管理设备备份。删除后那台设备下次备份会重新完整备份一次。

② 虚拟机与 Docker 的磁盘镜像

Docker Desktop、OrbStack、Parallels、UTM 都在本机放一个会不断增长的磁盘镜像。它们的共同特点是：镜像只增不减，即使你在容器里删了东西。

处理方式：Docker 先执行 docker system prune -a 清掉无用镜像和构建缓存，再到 Docker Desktop 的设置里收缩磁盘镜像大小。路径随版本变化，通常在 ~/Library/Containers/com.docker.docker/Data/vms 下，动手前先确认再删。

③ Xcode 与开发缓存

整个 ~/Library/Developer 都可能被算进系统数据：旧版模拟器运行时、构建缓存、真机调试支持文件。注意 Xcode/Archives 是你的发布存档，不能删。Xcode 五块空间详解 →

④ 本地快照（APFS snapshots）

没接外置硬盘时，Time Machine 会把还原点暂存在本机。你删掉的大文件可能还被快照「钉」着，所以删了东西空间却没回来。用 tmutil listlocalsnapshots / 查看。

⑤ 邮件附件与流媒体缓存

邮件客户端会把附件下载到本机；Apple Music、播客、TV App 和照片图库的缓存也会被算进来。这些通常各自几 GB，很少是主因，但加起来不可忽略。

自己动手量

三条命令，把来源定位出来

全部只读取，不删除任何东西。关键是第一条：把资源库下每个子目录按体积排序，最大的一眼就能看到。

① 资源库下谁最大（最大的排在最后）

du -sh ~/Library/* 2>/dev/null | sort -h | tail -15

② 看看有没有本地快照占着空间

tmutil listlocalsnapshots /

③ 单独确认设备备份有多大

du -sh ~/Library/Application\ Support/MobileSync/Backup

如果第一条命令的结果里出现了某个几十 GB 的目录，那基本就是它了。如果每条都不大，但「存储」里系统数据依然很高，那更可能是本地快照或者虚拟机磁盘镜像 —— 这两类不会被 du 正常统计，需要分别用第二、第三条思路去查。

安全边界

哪些能删、哪些别碰

  • 可以删：旧版模拟器运行时、构建缓存、真机调试支持文件、各类应用缓存与日志、无用的设备备份
  • 可以删：Docker 无用镜像与构建缓存（用 docker system prune -a，而不是直接删镜像文件）
  • 可以删：较早的本地快照（用 sudo tmutil deletelocalsnapshots，删完当前文件不受影响）
  • 别乱删：~/Library/Developer/Xcode/Archives —— 你的发布存档和符号文件
  • 别乱删：照片图库、iCloud 里的文件、微信聊天数据、Keychain、任何带「Library」但你不认识的目录

最后一条原则：在删掉一个你不认识的目录之前，先确认它是可重新生成的。名字像缓存不等于真的是缓存。

常见问题

关于系统数据

为什么我在访达里找不到「系统数据」？

因为它不是一个文件夹，而是「关于本机 → 存储」里的一个统计分类。macOS 把不属于应用程序、文稿、照片、音乐、邮件等分类的内容都归入其中，所以它由很多互不相关的路径拼成。

我删了很多文件，但可用空间没变，为什么？

很可能是本地快照把空间钉住了。用 tmutil listlocalsnapshots / 查看是否存在较早的快照。这类情况在没接外置备份盘、又开过 Time Machine 的机器上很常见。

系统数据会不会自己变小？

部分会。macOS 在空间紧张时会自动清理较早的本地快照和部分缓存。但设备备份、虚拟机磁盘镜像、Xcode 累积的运行时不在此列，它们不会自己消失。

用清理工具「一键清除系统数据」安全吗？

要看它实际删哪些路径。这个分类里混着你的设备备份、聊天记录和照片图库，一个不区分内容的「一键清除」风险很高。稳妥的做法是先定位到具体来源，再针对那一项处理。

网页能不能直接扫描我的 Mac？

不能。浏览器网页无法读取你本机磁盘的目录结构。本页提供的命令需要你自己在终端运行，真正需要本机深度扫描和批量处理的部分，要由你下载并运行的原生 App 完成。
